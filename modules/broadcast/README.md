# NVIDIA Broadcast audio module

This code-only Module API v1 package processes the graph's actual upstream PCM through a compatible, already running local NVIDIA Broadcast app. Installation does not require model paths or a voice profile. Select noise removal, room echo removal, both, or Studio Voice. The package is not yet in the official remote catalog; multi-endpoint device-host acceptance is still in progress.

Gateway discovery reads the documented per-user base64 gateway.json on each new connection, validates the loopback port range and verifies serverInfo.name before sending any audio paths or effect settings. Requests bypass network proxies, reject redirects, bound replies and do not retry non-idempotent submissions. Provider errors exclude private paths and raw messages.

Effect choices follow live microphone capabilities: noise removal, room echo removal, their combination, or Studio Voice with an advertised microphone profile. Studio Voice is never silently combined with incompatible denoisers. Effects are specified per private job; live device/effect configuration is not rewritten. Existing Broadcast processes are not stopped by this backend.

FileProcessor creates an owned temporary input/output pair, checks the exact completed job and output path, validates decoded mono PCM and removes temporary media after reading. A paused queue, user cancellation, skipped effect, failure or timeout raises an explicit error. It never resumes the global queue, retries a cancellation, resubmits a failed job or returns raw input as an enhancement result. On failure while waiting, cancellation targets only this backend's exact owned job.

The isolated worker detaches retained PCM from IPC buffers, preserves the source timeline, prepends context, retains lookahead and drains partial EOS. For the verified Broadcast 2.3.x backend it compensates approximately 70 ms content delay for denoising/echo removal and 40 ms for Studio Voice. Other versions require an explicit alignment override. Output contains exactly the input frame count; it does not include backend block padding. Reset clears retained speech and timing state.

Broadcast's documented gateway accepts file jobs rather than a live arbitrary-PCM stream. Default windows are therefore 2 seconds for denoising/echo removal and 8 seconds for Studio Voice, plus 100 ms lookahead and processing time. Advanced windows are bounded at 12 seconds; Studio Voice in realtime mode requires at least 8. This is a buffered effect, unsuitable for low-latency microphone monitoring. First preparation prewarms the effect with disposable silence. Runtime reports variable availability latency separately from compensated content delay.

Installed-package tests with paced 48 kHz input verified both noise removal and Studio Voice through split → enhancement → Loudness → merge, with three outputs (original, enhanced, merged). All 404,640 frames and timestamps survived EOS, the original branch was unchanged and the merge matched the sample average. This verifies graph processing, not yet physical-device playback. Hardware-dependent timings are not guarantees.

Each parent owns its worker and session directory. A minimal private job journal permits cancellation of its exact unfinished job after worker interruption, only after checking the job's source path. Unrelated jobs and the already running Broadcast app remain outside that ownership. A submission whose response is lost before returning a job ID cannot safely be cancelled by ID; it is never automatically resubmitted.

Apache-2.0 applies only to this original adapter code. No NVIDIA binaries, models or drivers are packaged; see LICENSE and NOTICE. An already installed/running compatible Broadcast app is required for this backend. The separate native Audio Effects SDK is another documented integration path, but is not installed or bundled by this implementation.
