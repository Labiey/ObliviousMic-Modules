# 文本翻译 / Text Translation

独立可选模块 `org.obliviousmic.translate`，输入和输出均为现有 TextSegment v1 的 `text` 端口。
无需模型权重、声音档案或额外 Python 依赖。代码采用 Apache-2.0，来源说明见 NOTICE。

## 连线

`ASR.text → translate.text → TTS.text → 音频设备输出`

或 `文本输入.text → translate.text → 文本输出.text`（可开启悬浮字幕）。
需要同时显示原文时，从上游 text 端口另接一路文本输出即可。
ASR、翻译和 TTS 各自的参数表独立管理；翻译目标语言会随输出传递给下游。

## 最简配置

- **百炼 Qwen（默认）**：填写自己的 `qwen_api_key`，选择目标语言即可。
  默认北京、`qwen-plus`；新加坡密钥请切换 `qwen_region`。使用所选模型的文本对话配额。
- **OpenAI 兼容**：选择 `openai_compatible`，填写 `base_url`、`model`，云端服务填写 `api_key`。
  本机 Ollama 示例地址 `http://127.0.0.1:11434/v1`，模型填本机已安装的真实模型名。
  LM Studio 可使用其本机兼容地址。模块不自动下载模型或启动这些服务。
- **Azure Translator**：选择 `azure`，填写支持文本翻译的 `azure_api_key`；区域资源还要填
  `azure_region`，全局资源可留空。**Azure Speech/TTS 密钥不一定具备 Translator 权限**。

`source_language=auto` 优先使用 ASR 提供的语言，否则交给引擎检测。
支持简体/繁体中文、英语、日语、韩语、法语、德语、西班牙语、俄语、葡萄牙语和意大利语。
默认目标英语 `en`。准确识别出源语言与目标一致时直接传递，不调用接口。
保存参数表后验证并应用处理图，再启动会话。准备处理图只检查配置，不发起翻译或计费请求。

## 实时行为和限制

- 翻译请求在独立进程内运行，由框架的异步队列调度，不在音频设备回调里等待网络。
- 默认 `final_only=true`，只翻译识别完成的句子，避免每次部分修订重复消耗额度。
  关闭后会逐个处理上游修订；译文仍以完整片段返回，不是模型 token 级流式输出。
- 保留片段 ID、媒体起止时间、修订号和 final 状态；新译文带目标语言。乱序、重复修订会被忽略。
- 默认单句最多 2000 字符，超时 25 秒，可在高级设置调整；内部响应大小和队列有上限。
  更长句子应在 ASR 处缩短分段。翻译失败会报错，不会把未翻译原文冒充成功译文发给 TTS。
- 无自动重试、无磁盘翻译缓存或会话聊天历史。密钥经宿主的私密参数存储和 IPC 传递，
  不进入命令行或公开错误。文本只发送给你选定的服务；本机 HTTP 仅允许回环地址，云端要求 HTTPS。
- 译文到达存在网络/推理延迟。媒体时间戳用于关联原句，不代表翻译可以零延迟完成。

LunaTranslator 的翻译引擎划分作为设计参考，其代码许可为 GPL-3.0；本模块独立实现官方协议，
不含其代码，也不继承其全部引擎列表。云端服务和本机所用模型的条款另计。
